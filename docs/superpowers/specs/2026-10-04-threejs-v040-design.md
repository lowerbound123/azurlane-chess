# 碧蓝推演棋 v0.4.0：Three.js 战斗场景设计草案

状态：用户已于2026-10-04批准执行，正在实施。2026-10-04。
基线：main/455275982ffe8117cef4be59d34577d52096444b，线上两站 v0.3.2。

## 目标与约束

用户要求：海战地图改用 Three.js，整个战斗场景改为 3D；暂用朴素模型；舰船是带名字的立牌，整个牌面持续朝向玩家；加入 3D 炮弹轨迹；版本 v0.4。

本方案将版本解释为 v0.4.0。范围包括海面、六角地图、岛屿、水雷、舰船立牌、飞机、鱼雷、炮弹与战斗效果。菜单、编队列表、指令面板、存档和教程文字继续用 Vue 平面 UI，叠在场景周边。游戏规则、AI、碰撞半径、伤害数值、回合顺序、存档格式和存储键保持兼容。

镜头采用推荐的可旋转斜俯视，默认拖动平移，显式旋转模式改变方位。发布前当前站点继续保持 v0.3.2。

## 方案比较

1. 推荐：Three.js 独立场景模块 + 现有 Vue 界面。沿用战斗引擎和规划层，渲染模块接收玩家可见的呈现数据并发出操作事件。迁移范围明确，便于逐项比较规则与存档结果。
2. 将游戏状态和全部界面迁入 3D：需要重新实现文本、表单与菜单交互，超出地图改造需要，不采用。
3. 保留 SVG 地图，仅叠加 3D 特效：改动小，但不能满足整个海战场景 3D 化，不采用。

## 视觉和镜头

采用深蓝海面、低多边形岩石岛屿、简洁光照和有厚度的棋盘边缘。285 个六角格在海面上清晰显示，地形高度只用于外观。先使用程序生成的几何体与文字纹理，不依赖外部美术下载。

推荐正交斜俯视镜头：近远格子及文字尺寸更稳定，便于战棋选格；场景仍为真实 3D，并支持旋转、俯仰、平移、缩放。默认从我方部署侧看向地图；限制俯仰范围，防止镜头钻入海面或进入不可读的低角度。提供全图、定位当前舰、恢复默认镜头。镜头状态仅属于显示层。

若选择固定斜俯视，锁定旋转/俯仰，仅保留平移缩放，其余结构不变。

舰船由海面底座、世界方向箭头和完整的姓名立牌组成。整个牌面采用 billboard 朝向，随镜头的方位及俯仰同步转动，文字不会背对玩家或变成侧面；底部锚点跟随舰船位置。姓名、阵营色和血条在同一牌面上，底座箭头独立表示真实舰艏方向。我方保持青绿，敌方保持珊瑚红。视野过滤在生成可见对象前完成，不借标签穿透暴露敌方位置。

飞机用简易机身与机翼组成，处于海面上方，有朝向和返航区别；鱼雷用细长体贴近水面运动，辅以短尾迹；水雷用球体与短棘；岛屿用低多边形岩块。

## 场景数据与模块边界

建议模块（具体文件名可在实施计划中细化）：

- `src/battle-map-3d.js`：Vue 生命周期与渲染器入口，镜头、ResizeObserver、选择事件和错误呈现。
- `src/scene/board.js`：海面、六角格、坐标、岛屿、水雷、迷雾与规划图层。
- `src/scene/units.js`：立牌、姓名纹理、血条、飞机/鱼雷模型与对象复用。
- `src/scene/effects.js`：炮弹、尾迹、命中、爆炸、伤害文本及对象回收。
- `src/scene/presentation.js`：可测试的坐标转换、可见性过滤、弹道采样与拾取语义适配。
- `src/main.js`：将原 SVG 地图替换为 3D 组件，连接现有 `clickHex`、`shipClick`、`truncateNode`、悬浮信息和镜头按钮。
- `src/playback.js`：输出连续播放时间并派发一次性效果事件，与现有插值和倍速保持一致。
- `src/engine.js`：仅增加呈现所需的炮弹/效果元数据，不调整结算规则。

引擎二维世界坐标 (x,y) 映射到 Three.js (x,height,z=y)，不使用现有 SVG 的25倍像素缩放。战斗引擎继续在原二维六角坐标中计算。

传给渲染模块的数据只包含当前玩家可见单位、已探索地形、公开水雷和友军计划；隐藏敌舰不得进入可点选列表。呈现层不回写插值坐标或镜头状态到存档。

## 完整操作迁移

迁移现有的部署选格/换位、选舰、航线追加/截断/撤销、鱼雷方向、主炮多次指定同格、飞机点目标/舰目标、扫雷、范围图层、全友舰计划、教程高亮。

通过 Raycaster 和海平面求交确定格子；可见立牌与可编辑路径节点具有明确的优先级。仅当前舰且处于航线模式的路径节点可截断航线；其他节点不抢夺武器点选。武器模式点击舰牌仍调用当前武器指令，而不是强制选舰。

桌面：左键点选/下令、左键拖动平移、滚轮缩放；保留右键点按追加航线，中键拖动或显式旋转模式控制旋转。手机：点按下令、单指拖动平移、双指缩放/平移，旋转模式用于改变方位和俯仰。设置拖动阈值，发生拖动、双指手势或取消事件后不得提交落点命令。

## 炮弹与战斗时间轴

已确认现状：主炮弹在回合开始记录目标，在回合末统一命中；当前效果只有落点，没有完整发射源。副炮/防空已有 from/at，但效果未携带精细的连续播放生命周期。

主炮增加稳定的弹丸编号、发射单位/阵营、发射世界坐标、目标世界坐标、发射时刻与原有落弹时刻。这些字段只用于回放，不改变伤害、命中或“开火舰沉没后已发射炮弹仍落地”的规则，也不让3D高度参与物理碰撞。

主炮表现为发射闪光→有高度的抛物线飞行→短尾迹→落点水花/爆炸→已有伤害提示。轨迹使用起终点插值与 `4*h*u*(1-u)` 高度曲线，起终点准确，中段有明显弧高。多发炮弹可同时表现，各自保留独立编号和效果；不得为了视觉错峰更改实际落弹时刻。

副炮使用较低的短弹道、防空使用对空曳光，分别依据原事件时刻播放；伤害归引擎，呈现不反向修改结算。效果按时间消费一次，不在每一帧重建同一次爆炸。倍速调整同时作用于移动、弹道和效果；跳过、退出、读档、重开清理所有临时动画。

弹道、尾迹和爆炸逐段遵循当前播放帧的视野。未知敌方发射点不显示标签或完整来源轨迹，不向渲染层传递可反推出隐藏舰位置的线段。主炮可以显示进入可见区域的末端轨迹及可见落点。

## 性能与故障处理

几何体/材质复用，静态地图只在地图变化时创建；单位对象按稳定ID更新变换；姓名纹理缓存，血量变化才更新牌面。限制像素比与阴影成本，暂不使用昂贵的水面反射或后处理。

一个渲染循环协调镜头与动画；页面隐藏或退出战斗停止无用绘制。卸载时释放 controls、监听器、纹理、材质、几何体与 renderer，处理 WebGL 上下文丢失。初始化失败时显示明确错误和重试/返回菜单，不出现空白地图。

目标为常见桌面和手机上的平稳动画；基于真实浏览器测量帧时间，不将 requestAnimationFrame 等同于所有设备保证60FPS。

## 实施顺序

1. 建立 Three.js 地图组件、坐标映射、镜头与格子拾取，验证部署与选舰。
2. 加入地形、迷雾、立牌与全部规划图层，迁移武器点选及教程高亮。
3. 补齐只用于呈现的效果元数据，接入飞机/鱼雷模型、主炮弹道、副炮、防空与爆炸。
4. 更新依赖 SVG 的交互测试，完成业务回归、浏览器操作及性能验证。
5. 运行指定版本命令 `node scripts/bump-version.mjs --set 0.4.0` 一次，构建两种路径并同步发布 GitHub Pages 与 ChatGPT Sites。

## 验收标准

- 全部285格正确呈现在3D空间，缩放/平移/允许的旋转后格子和舰牌可准确点选。
- 整个舰船牌面在所有允许镜头角度下面向镜头，舰艏方向箭头始终保持世界方向。
- 视野外敌方单位及未知地形不泄露；记忆地形、共享视野和公开水雷与现有规则一致。
- 部署换位、航线编辑、全部武器模式、叠加目标、存档和10课教学均可完成。
- 主炮有可观察的发射、空中弧线和落点；发射后舰船沉没仍完成炮弹播放与原结算。
- 在1倍/多倍速/跳过动画情况下，最终游戏状态相同；无重复特效、未清理弹丸或计时器。
- 桌面与手机横竖屏真实WebGL浏览器验证无空白、无相关控制台错误，交互与布局可用；记录帧时间和运行环境。
- 原引擎、规划、存档、播放逻辑测试全套通过；Vue/Happy DOM只验证界面状态和事件适配，WebGL画布使用真实浏览器验证，不保留隐藏SVG来维持旧测试假象。
