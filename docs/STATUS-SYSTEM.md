# 状态系统一期

舰船和飞机通过可选 `statuses` 字段持有状态。当前正式技能、命中和地图区域均不会自动施加状态；现有烟幕、雷达、封锁、护航维持原实现。

## 接入入口

游戏逻辑使用 `shared/status.ts` 的 `applyBattleStatus(game, targetId, definition, context)`。它检查目标和来源，并在施加时固化飞机对应的母舰 ID，确保飞机回收后仍能正确记录伤害归属。纯数据工具和测试可使用底层 `applyStatus`；其 `source` 必须是已经解析好的来源快照。

```ts
applyBattleStatus(game, targetId, {
  id: 'example-speed',
  name: '航速示例',
  kind: 'buff',
  icon: 'up',
  description: '仅说明接入方法，未绑定正式舰船。',
  effects: [{kind: 'speed', value: 1}],
}, {sourceId: ship.id, duration: 2});
```

`phase: 'execute'` 表示次回合开始生效；默认规划期施加当轮生效。`duration: null` 表示直到主动移除。使用 `removeStatus` 移除实例、`clearStatuses` 清除全部或某类状态。删除最后一个实例时删除字段，不写空数组。

## 效果与期限

- 航速、视野为固定增减；输出和承伤为比例增减（`.2` 表示 +20%）。不同生效状态的比例相加后转为倍率，最低为0。
- 舰船航速至少1、至多20，飞机航速至少0.1；基础 `cfg` 始终保留。舰载机不继承母舰的临时状态。
- 周期伤害/治疗采用固定数值，不再受武器增减伤影响；先汇总扣血，再治疗存活者，治疗不复活。
- 从R5起持续2轮，R5、R6生效并结算，R6末移除。实例记录绝对回合与上次结算回合，读取、重连、回放均不推进状态。
- 非叠层状态同源刷新，异源按 `strength` 取强；平级由稳定实例顺序决定。被覆盖的来源保留期限。
- `maxStacks > 1` 时每层独立记录来源与期限；满层替换最早到期层。执行期施加的新层在下一回合才接替旧层，保存允许不重叠的过渡实例。
- 单位最多64个实例、单类型最多32个生效层。已发射主炮/鱼雷、已布水雷保留输出快照；快照伤害上限与存档校验统一为安全整数上限。
- 来源消失不取消状态。舰船沉没、飞机击落或回收清除其持有状态；回收后不跨下一次出击保留。

## 结算和展示

行动/武器/回退 → 周期伤害 → 存活者治疗 → 死亡及母舰清理 → 据点结算和判胜 → 回放快照 → 到期移除。

状态图标投影到单位名称上方，6px图案、8px交互区域（按用户后续要求整体缩为原宽高的1/3）；显示前4种，其余合并到 `+N`。Tooltip支持悬浮、键盘和触屏，展示具体效果、层数、生效/结束回合、覆盖原因和允许公开的来源。投影使用地图现有动画循环。

网络和本地展示都过滤来源：隐藏来源的单位ID、母舰ID和名称不公开，实例ID替换为不含身份的展示ID。回放使用独立状态快照及帧回合，不从下一回合游戏状态取值。

旧存档缺少状态字段时按空处理；普通与教学存档版本、键保持原样。联机指令不允许提交状态字段。

## 开发验收

运行 `npm run dev` 后打开 `/tools/status-preview.html`，可检查多状态、溢出、叠层、等待生效、飞机、隐藏来源和回放到期。该页面仅在开发环境挂载，不在正式菜单或生产构建入口中。

核心测试：`tests/status.test.ts`；战斗、保存和协议：`tests/status-engine.test.ts`；组件交互：`tests/status-ui.test.ts`。教学存档和服务端AI测试另含状态专项用例。
